# ANTIFRAGILE INSURANCE (AFI)

**Strategic intelligence for the South African insurance industry — published monthly.**

AFI is a strategic intelligence publication for C-suite executives, senior underwriters, risk officers, regulators, institutional investors, and senior brokers across the South African insurance market. It is not a news summary or a regulatory update service — each issue makes one specific, defensible, non-obvious argument about the industry, applies four intellectual frameworks (Taleb's antifragility and tail risk, Thiel's monopoly and zero-to-one thinking, systems thinking, and behavioral economics), and is built to be uncomfortable for at least one powerful constituency.

Repository: `github.com/1906reblabs/mzansi-afi`

---

## Publishing schedule

- **Cadence**: monthly, on the last Thursday of each calendar month
- **Exception**: if the last Thursday of December falls within the final week of the month, the issue publishes on the preceding Thursday instead
- **Length**: 7,500–9,000 words per issue
- **Format**: nine fixed sections — Executive Brief, Black Swan Watch, Fragility Index, Hidden Profit Pools, Category Intelligence (8 sub-sectors), Second-Order Effects, Strategic Recommendations, The Contrarian Take, Closing Line
- **Special Editions** may publish between scheduled monthly issues in response to a major regulatory or catastrophe event. These are labelled "Special Edition" and do not consume the next regular issue number.

## How it's produced

Every issue is generated by a ten-agent editorial pipeline rather than written end-to-end by a single pass. Each agent has a dedicated skill file defining its mandate, output format, and quality standard.

| Order | Agent | Skill file | Produces |
|---|---|---|---|
| 1 | Memory Agent | `AFI-MEMORY-AGENT.md` | Pre-production memory brief; 5 persistent registers |
| 2 | Planning Agent | `AFI-PLANNING-AGENT.md` | Issue Brief, monthly thesis, agent briefing packages |
| 3 | Orchestrator | `AFI-ORCHESTRATOR.md` | Thesis distribution, pipeline coordination, quality gates |
| 4 | RAG Agent | `AFI-RAG-AGENT.md` | On-demand evidence retrieval across 7 knowledge domains |
| 5 | Research Intelligence | `AFI-RESEARCH-INTELLIGENCE.md` | Monthly Intelligence Brief (6 signal domains) |
| 6 | Risk Analyst | `AFI-RISK-ANALYST.md` | Black Swan Watch, Fragility Index |
| 7 | Category Analyst | `AFI-CATEGORY-ANALYST.md` | 8 Category Intelligence sections |
| 8 | Strategic Analyst | `AFI-STRATEGIC-ANALYST.md` | Hidden Profit Pools, Second-Order Effects, Strategic Recommendations |
| 9 | Writer-Editor | `AFI-WRITER-EDITOR.md` | Title, Executive Brief, Contrarian Take, Closing Line, full editorial assembly |
| 10 | Auditor | `AFI-AUDITOR-AGENT.md` | 7-pass quality audit, publication decision |

Nothing is published without Auditor clearance. Full pipeline and word-budget details live in `AFI-PROJECT-INSTRUCTIONS.md` and `AFI-WRITER-EDITOR.md` Section 2.4.

## Repository structure

```
.
├── index.html                  generated — site index, GitHub Pages root
├── issue-001.html              generated — published issues
├── issue-002.html
├── issue-NNN.html ...
└── afi-build/
    ├── afi_parser.py            parses issue + index content
    ├── build.py                 build runner (python3 build.py --all)
    ├── content/
    │   ├── index.md             5-line issues: YAML block, edited per new issue
    │   └── issue-NNN.md         full issue content, Markdown + YAML front matter
    └── templates/
        ├── index.j2             index page template
        └── issue.j2             issue page template
```

Content authoring is strictly separated from HTML compilation: an LLM (or editor) writes `issue-NNN.md` and the `index.md` entry; `build.py` handles everything downstream. Never hand-author HTML for a new issue.

---

## Building a new issue

```bash
cd afi-build
python3 build.py --all
```

This regenerates `issue-NNN.html` and `index.html` at the repo root from the current contents of `afi-build/content/`. See `AFI-BUILD-SYSTEM.md` for the full content schema.

### CI/CD
A GitHub Actions workflow (`build.yml`) triggers on pushes to `afi-build/content/**.md`, runs the build, and commits the generated HTML back with `[skip ci]`.

## Editorial frameworks

Every section applies one or more of:

- **Taleb** — antifragility, tail risk, convexity, skin in the game
- **Thiel** — monopoly dynamics, zero-to-one vs. one-to-n, contrarian truths
- **Systems thinking** — feedback loops, leverage points, nonlinear dynamics
- **Behavioral economics** — loss aversion, present bias, herding, availability bias

These determine what gets written and what gets cut — they are not decorative references.
